# Local intake of page-cited DCS literature

The publication register uses `scripts.build_chamber_database --publication-review`. It treats retrieval occurrences, report identities, cohorts and observations as distinct records. The active role-comparison protocol is in [chamber-publication-review.md](chamber-publication-review.md). The observed benchmark and its model gates are in [chamber-benchmark.md](chamber-benchmark.md).

1. Verify the candidate, article boundaries, primary bibliographic fields, local source hash, and exact physical page numbers. For meeting abstracts keep the published abstract separate from any full report and record shared cohorts.
2. Keep the local intake JSON and parse outputs below a Git-ignored research path. Set `repo_revision` to the full Git commit ID. Each report needs `report_id`, `source_sha256`, and integer `physical_pages` for the cited document. Local `pdf` is optional for a source with no usable file. Run `python -m tinydcs.literature_staging MANIFEST --output PRIVATE_DIR --dry-run`, then pass `--pdftotext PATH` for local page extraction. An image-only page is queued for OCR. Checksums identify the input manifest, output datasets and cached pages.
3. Use primary source pages to verify the extracted strata. Each observation has a `cohort_id`, `stratum_id`, setting, native endpoint and definition, ascertainment, numerator and denominator with original unit, overlap status, `physical_page`, `provenance_locator`, and a review status. Use JSON null for missing values and preserve source-reported rounded rates. Leave a reported case without a risk denominator intact. Model staging also records missing exposure profile, participant repeat and outcome window requirements.
4. Compare prospective public-register additions with existing report identities by identifier, citation, publication year and author, and then compare the cohorts. Add a dated snapshot and update its SHA-256 in the existing publication register manifest. The [ASMA pilot](../data/chamber/publication-review/retrievals-2026-11-20-asma-pilot.json) documents one verified aggregate test-abort endpoint and leaves the eligibility decision pending. For an already represented report, use the existing identity. Supply evidence for any new aliases or overlap links. Keep the screening log's decision stages and reviewer revisions intact.
5. Rebuild the publication database and inspect `review_record`, `review_search_observation`, and unresolved identity or overlap. Use the benchmark's frozen cohort and endpoint checks before adding model cohorts. The intake code produces two staging datasets and withholds training and pooling. The generated databases, full-text Markdown, OCR images and local Zotero keys stay in the private workspace.

## Operational flight surveillance

The [2026 AsMA abstract 220 intake](../data/chamber/publication-review/retrievals-2026-11-20-u2-care-asma-220.json) links the program and published meeting abstract under one report. The published abstract starts on p. 757 and finishes on p. 758. It reports three DCS cases in CARE-modified U-2 aircraft over 2014–2025, including one severe case, and rounded rates of 0.0088% per flight in modified aircraft and 0.0180% in unmodified aircraft. The modified rate of 0.1897 cases per 10,000 flight hours describes the same series on a different scale. Exact flight counts, flight hours and the unmodified case count are unavailable. The 1994–2010 comparator is linked to Hundemer's existing report. The operational observations are staged for descriptive use in the publication register. [Published abstract and Results](https://asma.kglmeridian.com/downloadpdf/view/journals/amhp/97/9/article-p1.pdf#page=97) · [AsMA program](https://asma.org/wp-content/uploads/2026/04/AsMA_Program-Book_edited_draft-1.pdf#page=142) · [Hundemer et al.](https://pubmed.ncbi.nlm.nih.gov/23066619/)

## Optional hosted parsing

The [reviewed-slice parser](../tools/llamaparse/parse.ts) uses the official LlamaCloud SDK. Start with its dry run. The versioned plan accepts up to three exact, verified PDF slices totaling ten pages. It reports the cost estimate at ten Agentic credits per page and expects documented current free-credit headroom and source rights clearance before live processing. The credential stays in the environment. Supply a local `pdfinfo` path and include each original source SHA-256, exact slice SHA-256, physical page list, rights evidence, and source privacy review. Approved submissions and subsequent reads use distinct commands so a known job can be polled without another submission. If a network interruption leaves the file or job ID unknown, reconcile that attempt before restarting. Store results in a local ignored directory and verify table cells against the original.
